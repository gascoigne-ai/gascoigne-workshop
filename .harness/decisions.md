# Decisions

Current facts only: the decision, its date, why, and what was rejected. Behavior is in `architecture/*.md`.

1. **Ebitengine with custom widgets** (user choice). Pure-Go GPU 2D with Wayland, X11 and one static-ish binary. Cost: every widget, text input and scroll area is ours.
2. **Protocols are a table; streaming and MCP are hand-written, gRPC is official.** `model.Protocols` rows map to implementations in `request/port.Registry`; nothing compares a protocol (2026-11-18). The table is split because the UI half names panes and the model half is needed by packages that may not import the UI or `proto`. An unknown or empty protocol text is a parse error at the edge (user, 2026-11-18). WebSocket and MCP are written by hand: the needed part is small, the rules allow no new dependency, and the raw message log the UI shows is what the client already handles. gRPC uses `google.golang.org/grpc` and `protobuf` (user, 2026-11-06), since HTTP/2 and protobuf are not a small part; no code generation. A gRPC code maps to an HTTP status (`OK` 200, `NOT_FOUND` 404, `UNAVAILABLE` 503, others 500), so the status pill and `status == 200` assertions work; a call never made is `Response.Err`.
3. **The toolkit is three layers, independent of the app** (2026-11-11, user's correction of an earlier attempt). `core` holds primitives, `view` the framework, `widget` every component with its own drawing, input or state. Like Qt, GTK and Flutter, the base holds no component. `view` cannot import `widget`, so a component leaves `view` only when nothing there uses it and what the runtime calls goes through an interface. Runnable examples are one package, `uitoolkit/examples`, because `go vet` forces the `Example_xxx` form. `vml` was renamed `view` (user's choice); `VML` is the template language.
4. **Views are markup templates** (2026-11-12, user's choice; reopens the earlier "tab strips, tables and App features stay Go"). Templates build the same `*view.El` tree as the Go builders; bindings are lookups, directives `if` and `for`, no expressions, so logic stays in Go and templates stay checkable. Methods are not reachable from a scope (one name, two meanings). A view moved to markup may not change a pixel; golden shots (decision 5) and `view.Dump` pins are the oracle. Templates are inline `const` strings in their view's Go file, parsed once with `markup.Must` (user, 2026-11-15); the app has no `.vml` files. Views are rebuilt every frame: state stays in the app, no diffing, no reactive graph.
5. **UI changes are checked against golden shots drawn with software GL** (2026-11-12, user's choice over a Go rasterizer or Xwayland). Ebitengine draws only through a GL context, so the program runs on Mesa llvmpipe under Xvfb; the test is skipped without `xvfb-run` except in CI.
6. **Themes are data, per control.** Colors, radii, gradients and outlines are embedded JSON theme files, so the look can change without touching widgets; elements name a control style rather than a gradient. Own small JSON, because it carries radii and gradients and parsing stays in the standard library.
7. **Collections are a tree of JSON files** (`collection/adapter/store`). One directory per folder (`folder.json`: name, root variables, child order), one `*.req.json` per request, stable key order, so diffs are small. File names are slugs made unique with `-2`, `-3`; the real names live inside. Credentials go to `.secrets.json`, listed in `.gitignore`, never into request files. Saving and Delete remove only files the store wrote; other files stay. Files the order list does not know load after the listed ones, by name. Collections are managed from the UI (user, 2026-11-15).
8. **Native file dialogs shell out to osascript (macOS), PowerShell (Windows), zenity, kdialog, yad, qarma or matedialog**, no widget and no dependency. On Linux the order follows the desktop, read from environment variables, no D-Bus (user, 2026-11-15). Without a program the app opens its in-app browser (decision 18).
9. **settings.json is one schema table.** `settings.Schema` lists every key once; the form, raw view, validation, completion, reset and `Minimal` all read it. The file holds only what differs from the defaults. A valid raw edit applies at once; an invalid one changes nothing.
10. **Client configs are `.workshop.{yaml,json,toml}`; debug builds carry example endpoints** (user, 2026-11-10). TOML uses `github.com/BurntSushi/toml` (user-approved), YAML the `miniyaml` subset reader.
11. **`internal/` is `<domain>/<role>/<package>`** (user's choice, 2026-11-07). Rules in `rules.md`; `internal/layers_test.go` has no exceptions. `workspace` is the composition root and may also import other domains' ui and controller (user, 2026-11-07, 2026-11-10); adapters reach it only through ports, and a nil port falls back to a null one so tests need no desktop. Go cannot split a type's methods across packages, so everything that reads and writes the `App` is one package, `workspace/ui/app`; a feature that needs little of it is its own package behind a `Host` interface with a fake-host test. Code with no widget goes to a `controller` first.
12. **Task 031 closed unrun** (user, 2026-11-07): Windows and macOS are untested; the blocked items are in `release.md`. go-winres was approved on 2026-11-18 for the Windows icon.
13. **State changes follow Model, Msg, Update, Cmd** (user, 2026-11-10). `Update` is pure (no I/O, goroutine or clock). A UI handler applies its message at once, because the next line needs the new state; the bus carries only what goroutines report. `Update` may type-switch on its message: the one place "table over switch" yields. `prefs` messages may carry functions: the page decides what changes, the App owns the settings. Accepted gaps: settings `Persist` and image decode stay on the UI goroutine. A second tree build per frame happens only after a handler or a stale flag (2026-11-20); a revision counter was rejected (one missed bump loses an edit), and a differential test catches a missed signal. Rejected: signals, React-style diffing, more controllers behind closures.
14. **A row that overflows takes the overflow from its `Shrink` children** (2026-11-14, user's choice over a lower chip cap). `Shrink()` is explicit rather than a reading of `Ellipsis`, because the child that gives room is often a container.
15. **Dialogs are in-app floating windows with a title bar of their own** (2026-11-14, user's choices). Ebitengine has one OS window per process. Layout keeps the dialog inside the Stack and writes the kept offset back to the state, the one place layout writes. The look is in `style.md`.
16. **A System page in the settings shows the system and GPU rendering** (2026-11-14, user's request). The Ebitengine side is an injected function, so tests need no display.
17. **Several collections are open at once, each known by its folder** (2026-11-15, user's decisions). Identity is the folder. Each collection has its own active environment and a request expands with its own collection's variables only, so nothing leaks across. History keys by folder and path; the first or an unsaved collection keeps the bare path, so older history reads. Roots reorder by menu, not by drag, because a drag moves a node within its collection. Closing the last collection leaves an empty tree with Open and New and makes nothing on disk; closing an unsaved, edited one asks first. Moving across collections is decision 25.
18. **Without a dialog program, Linux gets an in-app file browser** (2026-11-15, user's decision). It is the last row of the chooser table and keeps the `FileDialog` contract. A D-Bus portal was rejected: it needs a client library or a hand-written protocol and a running portal service, while the browser needs nothing installed. Detection was widened so the browser is rarely needed (user, 2026-11-15). A muted footer line names the desktop's dialog program (the default taken; the user did not choose a place).
19. **gRPC reads `.proto` files with protocompile** (2026-11-15, user's decisions). It gives the same descriptors as server reflection, so calls use one code path. Rejected: a hand-written parser on protobuf's `protoreflect` (a parser and linker to keep up with the language) and an external `protoc` (a program to install, output to read back). Files and import paths are per request; paths inside the collection folder are relative so it can move. The choice is a Proto tab of the gRPC request (user, 2026-11-15). Import paths are typed, since the file dialogs pick files only and a folder mode would touch every dialog program.
20. **The dev build has its own user directory** (2026-11-15, user's decisions). Dev uses `gascoigne-workshop-dev`, release `gascoigne-workshop`, so the dev build reopens what it remembered, like an install. An unsuffixed directory from an earlier dev build is left alone: no migration, no warning.
21. **Requests that run commands or read files ask first** (input audit, 2026-11-16, user's decisions). An MCP `stdio:` command or a file outside the collection asks once; Allow is remembered per command line and absolute path. A prompt and not a refusal, because the file browser stores absolute paths and refusing them would break normal attaching. Decided against a prompt for a `.workshop.*` config in the working directory. `.proto` imports cannot leave their import paths (no prompt). Postman export leaves out literal credentials and secret variable values and keeps `{{variable}}` references. Values captured by a `set` assertion are `Literal` and never expanded again (user). Oversized input is limited rather than refused where it can be (user's answers; see `architecture/limits.md`).
22. **Every saved file carries its own version** (2026-11-18, user's decisions). A missing version is 0. The version is per file, not per collection, and lives in each adapter's wire type, not the model. How a file from a newer build is treated is the user's answer (2026-11-18), tabled in `architecture/persistence.md`. Accepted (user, 2026-11-18): the first save after upgrading rewrites every collection file once, a one-time diff under version control; CHANGELOG.md says so. Moving the decision-17 fallbacks into a version-0-only reader is a later task.
23. **The name Postman is allowed where it names the import and export format** (user, 2026-11-18). The format is a file the workshop reads and writes, and a generic name would hide which format a user can import. Everywhere else, other tools stay unnamed.
24. **The App reaches the user's files only through `port.Folders`** (2026-11-18). The calls run off the UI goroutine. `Folders` was widened rather than a second port added: it is already the user's file system at the same boundary and already wired, and a second port would be a second adapter over the same disk. The file body check is one record per tab; a shared map was rejected (tabs seldom share a file; it needs pruning). Revisit when the check must notice a file appearing without the path changing, or when `Folders` outgrows the browser and named files (then split it).
25. **Moving and copying between collections** (2026-11-18, user's decisions). Drag moves, Alt at release copies. A clashing name is renamed ("x 2"), also within one collection. Variables are never rewritten; history is not migrated; an unsaved target is allowed. The target is written before the source, so a failed write loses nothing. Alt-drag is unreliable where a window manager takes Alt, so the row menu has Move to... and Copy to.... Rejected: drag only without a menu, cut/copy/paste in the tree.
26. **The atomic file write and the config path live in the model `settings/model/userdir`** (2026-11-19, user's choice). Five adapters copied "temp file, then rename"; adapters may not import each other and every domain may import a model, so `WriteFileAtomic` sits beside `userdir.Path`, with no new package and no layer exception. Rejected: an adapter package shared across domains (needs a layer exception), a copy per domain.
27. **Toolkit API exceptions of rules 1, 7 and 11** (2026-11-20). Rule 1: `Round` is not a per-side family but the corner masks a panel needed (`RoundT`, `RoundB`, `RoundBL`); a mask is added with the panel that needs it, not ahead. Rule 7: state types are values (`NewTextField`, `NewTextArea`, `NewMenu`); `OpenMenu` stores a pointer to its own copy. Rule 11: `core.Ctx.Menu` stays `any`, because `widget` owns `MenuState` and `core` cannot name it, the price of decision 3's "any element opens a menu without a host"; `core.Ctx.FocusOwner` is typed, since its interface uses no widget type (`core.Focuser`, aliased by `view.Focuser`). Exported mutable tables are copies; `engine.KeyNames` is unexported (no reader outside `engine`).
