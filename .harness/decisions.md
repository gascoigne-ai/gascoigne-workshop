# Decisions

1. **Ebitengine with custom widgets** (user choice). Pure-Go GPU 2D with Wayland/X11 support and one static-ish binary. Cost: every widget, text input and scroll area is ours. First milestone keeps input single-line and the code viewer read-only.
2. **Protocol registry.** REST is real in milestone 1; WebSocket and MCP are registered stubs that return "not implemented", so the UI path is exercised end to end.
3. **Sibling bare repo** like the other gascoigne projects; shared harness via `.harness/common`.
4. **Toolkit split: `widget` + `view` + app.** The reusable GPU toolkit and the view DSL are public packages with no knowledge of requests or protocols, so they can move to their own repo later. The app only holds state, handlers and views.
5. **VML is a Go-native DSL, not a template language.** Typed builder functions with chained attributes and Vue-like `If`/`For`/`Field`. The Go compiler checks it, refactors keep working, and no parser, reflection or generator is needed. A text template syntax can be added later as another front end that emits the same nodes.
6. **Views are rebuilt every frame.** State stays in the app; there is no virtual DOM diffing or reactive graph. Widgets that need identity across frames (text field, code view) take a pointer to app-owned state.
7. **Streaming protocols and a hand-written WebSocket client.** `proto.Protocol` keeps its one-shot `Send`; protocols that stay connected also implement `proto.Streamer.Connect`, which returns a `Session` (an ordered `Events()` channel, `Send`, `Ping`, `Close`). A slow consumer blocks the reader instead of losing messages. The standard library has no WebSocket, and the rules allow no new dependency, so `internal/proto/ws` implements RFC 6455 (handshake, framing, masking, fragments, ping/pong, close codes) in about 400 lines; its server-side handshake exists for tests.
8. **Themes are data, per-control.** Colors, corner radii, gradients and outlines live in embedded JSON theme files (variables, colors, controls), not in Go, so the look can change, be flattened or squared (settings `corners`, `flat`) without touching widgets. Elements name a control style (`view.Control`) instead of picking a gradient or border themselves. The format is our own small JSON rather than a CSS or editor-theme dialect: it has to carry radii and gradients, and parsing stays in the standard library.
9. **Collections are a tree of JSON files** (`internal/store`). One directory per folder (`folder.json` with the name, root variables and the child order), one `*.req.json` per request, indented with a stable key order so diffs are small and git-friendly. File names are slugs of the names, made unique with `-2`, `-3`; the real names live inside the files, so any characters survive. Credentials (token, password, API key value) are written to `.secrets.json`, keyed by request path and listed in `.gitignore`, never into request files. Saving only removes `*.req.json` files and folders with a `folder.json`; other files in the workspace are left alone. Loading puts files the order list does not know after the listed ones, by name, so hand-made files appear.
10. **MCP is a hand-written JSON-RPC client** (`internal/proto/mcp.go`), no SDK, for the same reasons as decision 7: the needed part of the protocol is small (initialize, lists, calls, ping over streamable HTTP and stdio), the dependency would be large, and the raw message log the UI shows is simply what the client already handles. It implements `Streamer`; `Send` is the one-shot form (connect, `tools/list`). A server URL starting `stdio:` runs the rest of the line as a command.
11. **Declarative views are HTML-style templates on the same runtime** (`uitoolkit/component`, named after Vue's components). A template lives in a `.vml` file (embedded or read from a folder) or inline in Go source through `component.Must`. A `.vml` file is XML with HTML's leniency (bare flag attributes, entities), parsed with `encoding/xml`: no new dependency, no second runtime. It builds the same `*view.El` tree as the Go DSL, so the two styles mix and a view can move from Go to a template one at a time. Elements and attributes are tables (`elements`, `attributes`), bindings are `{{path}}` lookups in a `Scope`, there are two directives (`if`, `for="x in xs"`) and `onclick` names a `func()` of the scope. No expressions and no code in templates: logic stays in Go, which keeps templates checkable. Errors name file and line. Tag `col` is not an HTML void element here because no HTML auto-close table is used.
12. **Native file dialogs shell out to zenity or kdialog** (`internal/filedialog`), no widget and no dependency. The dialog runs off the UI goroutine and its answer comes back through `App.later`; without either program the app asks for the path as text, so nothing depends on a dialog being present. Used by `Save body...` and the file body's `Choose...`.
13. **gRPC uses the official `google.golang.org/grpc` and `protobuf` modules** (approved by the user on 2026-11-06, with their transitive requirements: `golang.org/x/net` and `genproto/googleapis/rpc`). Hand-writing HTTP/2 framing and protobuf is not a small part of the protocol, unlike decisions 7 and 10. Nothing else is added: reflection is read with grpc's own `grpc_reflection_v1` and `v1alpha` clients, messages are `dynamicpb` with `protojson`, so no `.proto` files and no code generation. `Request.URL` is `grpc://host:port` (plain) or `grpcs://host:port` (TLS, `InsecureTLS` honored), `Request.Method` is `package.Service/Method`, `Request.Body` is the message as JSON. A call that reached the server shows as a response whose `Status` is the usual HTTP equivalent of the gRPC code (`OK` is 200, `NOT_FOUND` 404, `UNAVAILABLE` 503...; unlisted codes 500) and whose `StatusText` is the code name, so the status pill and `status == 200` assertions work unchanged; a call that could not be made (no server, no reflection, bad JSON, unknown method) is `Response.Err`. Unary calls only.
14. **Tab strips, tables and the App-bound features stay Go code** (closes tasks 018 and 021). Templates (decision 11) take what a scope can hold: values, lists, click handlers, slots. A tab strip needs middle-click, right-click and drag-over handlers and drag state; a table needs a `TableSpec` full of callbacks and state objects; both would only move the same Go behind slots, which hides it from the compiler for no gain. Likewise the panes, environments, workspace saving, overlays and shortcuts in `internal/ui` read and write the one `App` state; an app-state interface to split them is built when one of them gets a second user, not before (rules.md: no speculative abstractions). Reopen either when a second consumer exists.
15. **settings.json is one schema table; the raw editor reuses `TextArea` as it is** (task 030). `settings.Schema` lists every key once (title, description, kind, allowed values, range); the form, the raw text view, validation, completion, per-setting reset and `Minimal` all read it, so there is no second list. The file holds only what differs from the defaults; reset removes the key. The raw view needs no new widget: errors are shown by coloring the offending key through `TextArea.Styler` (it receives a line, so a problem is matched by its quoted key) and a list under the editor with line and column for syntax errors, and completion is a menu opened by Ctrl+Space at the caret (the menu the URL field's variable completion already uses) rather than a popup inside the editor. This differs from the first idea (a completion hook and marks on `TextArea`); it was chosen because it adds nothing to the toolkit and covers the same need. A valid raw edit applies at once and is written as typed; an invalid one changes nothing. The file is checked for outside changes every 30 frames; a good change is applied to the form and the raw view, a bad one is reported and ignored.
16. **The `vml` package is named `view`** (task 029, chosen by the user from `view`, `element` and `kit`). It holds the element API (`Row`, `Col`, `Text`, `Field`...), the widgets with state, layout and the runtime, which are all "what is drawn and how it reacts"; `view.Row`, `view.Layout` and `view.Dump` read plainly where the name is spelled out, and `internal/ui` dot-imports it as before. The mechanical rename moved `uitoolkit/vml` to `uitoolkit/view` and changed the import path, the package clause, the qualified uses, the layer test and the docs; no behavior or test assertion changed. `VML` stays the name of the template language and `.vml` the template file extension (decision 11): the markup is still VML, only the Go package got a plainer name.
17. **`internal/ui` is split by feature, in stages, behind `Host` interfaces** (task 029, chosen by the user from a full split, a staged split and a file-prefix regrouping). A Go package cannot hold methods of a type from another package, so everything that reads and writes the one `App` (tabs, panes, sidebar, environments, workspace, shortcuts) stays in `internal/ui`; decision 14's reasoning (no app-state interface until a second consumer exists) still holds for those. A feature that needs little of the `App` moves to `internal/ui/<feature>`: it owns its state in a value type the `App` embeds as a field (`calltrace.Log`, `sentlog.Log`), draws its own view, and asks the `App` through a small `Host` interface for what it cannot do itself (window size, toasts, request lookup). The package has a doc comment, tests with a fake host, and never imports `internal/ui`. One feature per commit; behavior and assertions do not change, only names and imports in the tests that moved. This reverses decision 14 for these features only.

18. **Task 031 closed unrun** (user decision, 2026-11-07). Nothing was run on Windows or macOS: window and HiDPI, clipboard, file dialogs, browser opener, Cmd shortcuts, font folders and IME are untested there; the Windows `.exe` has no icon (a `.syso` needs a tool that is not an approved dependency; the window icon is set at run time); `release.yml` (macOS bundle, Windows zip) has never run on a real tag. Reopen as a new task when a machine, a CI runner with a display or the tool approval exists.
19. **`internal/` is grouped by domain, then by role** (task 033, chosen by the user, 2026-11-07; replaces decision 17's rule that features split out of `internal/ui` into `internal/ui/<feature>`, which now go to their domain's `ui` role). A package path is `internal/<domain>/<role>/<leaf>`; leaf package names and identifiers stay, so a move changes imports only (`internal/request/model` is package `model`). Domains: `request`, `collection`, `response`, `settings`, `workspace`, `environment`. Roles: `ui`, `controller`, `port`, `adapter`, `model`. `request/model` holds the shared data types (`Request`, `Folder`, `Response`) and other domains import it as a small public API. The existing `collection` and `settings` packages sit one level down (`collection/model/collection`, `settings/model/settings`). Rules, enforced by `internal/layers_test.go`: model imports only model; port imports model and port; controller imports model, port and controller; ui and adapter import model, port and controller but never each other; another domain is reached only through its model or port. Cross-domain edges that existed (`settingsui` using `respview`, `openapi` using `proto.Skeleton`) are removed by moving code, not allowed. Packages still at the top of `internal/` are not checked until they move; known violations inside moved packages are listed in `exceptions` in the test and only shrink.
20. **Package map of decision 19** (task 033, 2026-11-07). `model` → `request/model`; `proto` → `request/adapter/proto`; `assert` → `request/controller/assert`; `ui/calltrace` → `request/ui/calltrace`; `collection` → `collection/model/collection`; `store`, `openapi`, `postman`, `miniyaml` → `collection/adapter/*`; `jsonview`, `textfmt` → `response/model/*`; `respview`, `ui/sentlog` → `response/ui/*`; `history`, `preview` → `response/adapter/*`; `settings` → `settings/model/settings`; `appearance` → `settings/controller/appearance`; `fonts` → `settings/adapter/fonts`; `ui/settingsui` → `settings/ui/settingsui`; `state`, `filedialog` → `workspace/adapter/*`; `appicon` → `workspace/ui/appicon`; the `App` (old `internal/ui`) → `workspace/ui/app`, which keeps package name `ui` and is imported with an alias, so no identifier changed. The `environment` domain has no package yet; it appears when the environment chip and dialogs leave the `App`. Packages that mixed roles were split where a rule edge would otherwise break: the MCP list parsers, `Skeleton` and the tool form fields moved from `proto` to `request/model` (so the OpenAPI importer no longer imports another domain's adapter); the sent-request type and `SentStore` are `response/port`, implemented by `history.SentLog`; font families and their lookup are `settings/model/fontfamily`, `settings/port.FontStore` is implemented by `fonts.System`; `jsonview.Kind.Style` names the theme style so the settings dialog does not import `respview`. Views get adapters through their `Host` (`SentStore()`, `FontStore()`). The `App` is the composition root and still imports other domains' adapters, controllers and views; the such imports (none left after ports for the file dialog, preview, history, fonts, collection store, UI state and protocols, and the pure importers moved to model) are the `exceptions` in `internal/layers_test.go`, to be removed by splitting it. `settings/model/settings` still reads and writes the file (I/O in a model package) until a settings port exists; the layer test only checks imports of this module, so it does not flag that.
21. **Adapters are wired in `cmd/workshop`, not in the App** (task 033). The App takes ports through `Options` (`Files port.FileDialog`, `Previews port.BodyPreview`, `History func(dir) port.History`, `Fonts port.FontStore`) and falls back to a null one (`noFileDialog`, `noBrowser`) when a port is nil, so tests and screenshots need no desktop. Tests that want a real or fake adapter set `a.files` or `a.previews` after `NewApp`. The same route is used for each port that follows; the old test-seam fields `chooseFile`, `hasFileDialog` and `openBrowser` are gone.
22. **`assert` and `appearance` are model packages** (task 033). Both are pure rules with no I/O (the assertion language over a response; theme and colors built from settings), and the App needs them directly, so they are `request/model/assert` and `settings/model/appearance`, which other domains may import. No `controller` package exists yet; the role is for the App's state and decisions once it is split.
23. **Importers are model packages; the collection store is a port** (task 033). `openapi`, `postman` and `miniyaml` only turn bytes into model values and back, so they are `collection/model/*`. `collection/port.Store` is what the App saves and loads through; `store.Files` implements it and `Options.Store` hands it in.
24. **UI state is a model plus a store port** (task 033). The remembered window, tabs and pane sizes are `workspace/model/state`; reading and writing `state.json` is `workspace/adapter/statefile` (formerly `adapter/state`, renamed so both can be imported without an alias), behind `workspace/port.StateStore` and `Options.States`. `State.Save(path)` became `statefile.Save(path, state)`.
25. **`workspace` is the composition root and may import other domains' `ui`** (task 033, chosen by the user, 2026-11-07; amends decision 19's "another domain only through model or port"). The window is assembled from `calltrace`, `respview`, `sentlog` and `settingsui`, each already a self-contained view behind a `Host`. Their adapters stay forbidden: the App gets those through ports in `Options`. `internal/layers_test.go` has the rule as `compositionRoot` and cases for it.
26. **Protocols are a port built in `cmd/workshop`** (task 033). `request/port` holds `Protocol`, `Registry` (name table with `Send`, `Connect`, `Names`), `Streamer`, `Session`, `Event` and the sampling types, plus `ProtocolConfig` (cookie jar, proxy, certificates, sampler) and `GRPCMethods`. `proto.Configured(config)` builds the registry; the App calls `Options.Protocols` whenever it needs a new one (start, clearing cookies) and uses `Options.GRPCMethods` and `Options.Curl` for gRPC reflection and "copy as cURL". `proto` keeps type aliases of the port names so the adapters did not change. cURL parsing, GraphQL schema parsing, `ShellSplit` and `ErrCancelled` are pure and moved to `request/model`; `Curl` stays in the adapter because it encodes file bodies. `exceptions` in the layer test is empty.
27. **`workspace` may import other domains' `controller` too; GraphQL schema menu and gRPC picker stay in the App** (task 033). The first controller is `environment/controller/envs` (active environment of a collection and how add, rename, delete move it); the composition root assembles state as well as views, so decision 25 covers ui and controller. Adapters still come only through ports. The GraphQL schema menu and the gRPC method picker were not split: each is a few lines of menu wiring over tab state, `dispatch` and `openMenu`, so a `Host` would have mirrored most of the App (decision 14's reasoning).
28. **The clock is a port** (task 033). `workspace/port.Clock` is what the App reads time from (toasts, save debounces, caret blink); `systemclock.Clock` is the wall clock and `cmd/workshop` sets `Options.Clock`. A nil `Clock` falls back to `time.Now`, since a frozen zero time would stop toasts expiring and tests build the App without adapters; tests that need a fixed time pass a fake in `Options`.
29. **The settings file is a port** (task 033). `settings/model/settings` keeps the schema and the text rules (`Decode`, `Encode`, `Parse`, `Validate`, `Minimal`) and does no I/O. `settings/port.SettingsStore` (`Load`, `Save`, `WriteText`) is implemented by `settings/adapter/settingsfile`, which also owns the default paths (`DefaultPath`, `ThemesDir`, `DefaultWorkspace`). The App takes it as `Options.SettingsFiles` (nil reads the defaults and cannot save) and hands it to `settingsui` through `Host.SettingsStore`. `SettingsStore` also has `ReadText` and `Stat` (a `settings.FileStamp`), which `settingsui` uses for its change polling and raw view through `Host.SettingsStore()`; the dialog does no file I/O itself.
30. **Colors page and shortcut editor leave the App; the environment chip stays** (task 033). `settings/ui/colorpage` and `settings/ui/shortcutpage` are pages of the settings dialog, each behind a `Host` that the App implements with `pageHost` (settings, `Edit`, theme colors, text menu, and for shortcuts the action list). The App keeps the shortcut table because each row runs an `App` method. The environment chip and its menu are about 35 lines of wiring over `openMenu`, `prompt`, `confirm` and the selection in `environment/controller/envs`, which already holds the logic; a `Host` would mirror those App helpers, so they stay (decision 27's reasoning).
31. **The App split follows controller plus self-contained views** (task 033, user agreed 2026-11-10, after advice). State that would survive a different UI goes into a `controller` package per domain; widget state (`TextField`, `CodeView`, `ScrollState`, find, auth inputs) stays in the view side, which embeds or holds the controller value and calls its methods directly: no message type, no bindings. `internal/layers_test.go` rejects any `uitoolkit` import from a controller. First slice: `workspace/controller/tabs.Tab` (request, saved copy, response, send number), embedded by `reqTab`; the next slices move the tab list, find and the rest, one field group per commit, renamed with gopls.
32. **What stays in the App** (task 033 closed, 2026-11-10). Controllers hold what has no widget in it: `workspace/controller/{tabs,autosave,toasts}`, `collection/controller/tree`, `response/controller/viewer`, `environment/controller/envs`. The App stays one package (Go methods cannot span packages) and keeps the handlers that tie those to widgets and prompts: tree and workspace handlers (`treeops.go`, `workspace.go`), the find bar and response view driving a `CodeView` (`panes.go`), and the context menu and dialog state (`overlay.go`, whose `menuItem` and `dialog` carry closures and a `TextField`). Moving them would turn each into a controller that calls back into the App or a Host mirroring it (decisions 14, 27, 30). A new rule or piece of state that has no widget in it goes to a controller first.
33. **Settings edits have two entry points** (task 034, 2026-11-10). `saveSettings` applies an edit, rebuilds the protocols when a network setting changed, refreshes the open tabs when the response view changed, and persists; every caller gets that. `changeSettings` is `saveSettings` plus `colors.Forget`, for the settings dialog's own controls only: the Colors page edits through `saveSettings` (`pageHost.Edit`) while a hex field is being typed, and forgetting the fields then would wipe it.
